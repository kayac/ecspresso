# Differences of ecspresso v2 and v3.

See also [v3-plan.md](v3-plan.md), issues and pull requests labeled `v3`.

## Breaking changes (CLI / configuration)

- `required_version` in a configuration file that excludes v3 (e.g. `>= 2.0.0, < 3`) makes ecspresso v3 fail to load the configuration. Update the constraint when you upgrade.
  ```yaml
  required_version: ">= 3.0.0, < 4"
  ```
- YAML configuration files must be valid YAML before template rendering. Template literals that begin a YAML scalar value must be quoted. JSON and Jsonnet configs are unaffected. (#1023)
  ```yaml
  # NG in v3
  region: {{ must_env `AWS_REGION` }}
  # OK
  region: "{{ must_env `AWS_REGION` }}"
  ```
- Remove `filter_command` configuration field. Use `ECSPRESSO_FILTER_COMMAND` environment variable or `--filter-command` CLI flag instead. (#1024)
- Remove deprecated `exec` flags (`--port-forward`, `--local-port`, `--port`, `--host`). Use `exec portforward` subcommand instead. (#1025)
- Remove deprecated `tasks` flags (`--find`, `--stop`, `--force`, `--trace`). Use `tasks find`, `tasks stop`, `tasks trace` subcommands instead. (#1025)
- Remove `diff --unified` / `--no-unified` flag. Unified diff is now always used. (#1027)
- `Duration` handling changed: plain numbers and pure-digit strings in configuration are interpreted as seconds, not nanoseconds. String durations like `"30s"` or `"10m"` are unaffected. (#1028)
- `rollback` command now requires an active deployment by default. If no active deployment is found, it returns an error. Use `--with-previous-task-definition` to explicitly find and deploy the previous task definition revision (the v2 default behavior). (#1047)
- `run --count N` (N > 1) waits for every started task and fails if the watch container of any task fails. v2 waited only for the first task. With multiple tasks, container log lines are tagged with the task ID. With `--wait-until=running`, a task that has already stopped no longer fails the wait; its exit status is checked instead. (#1113, #1117)
- `--wait-until` defaults to `deployed` in every command that waits for a service deployment. `rollback` and `wait` defaulted to `stable` in v2. Pass `--wait-until=stable` for the v2 behavior. (#1146)
  - `deploy` applies `--wait-until` also when it creates a new service. v2 always waited for the service to be stable.
  - With `--wait-until=deployed`, a command that starts no service deployment (e.g. `deploy --skip-task-definition --tasks N`) waits for the service to be stable. v2 returned without waiting.
  - `wait --wait-until=deployed` (and `paused`) waits for a deployment in progress that was started before the command. v2 looked only for the deployments started after the command, and returned immediately.
- Commands that describe the service (`deploy`, `diff`, `status`, etc.) fail when `DescribeServiceRevisions` fails, instead of treating revision-only attributes such as `monitoring` as unset. The IAM principal needs `ecs:DescribeServiceRevisions`. (#1107)
- Keys in definition files and the configuration file are case-sensitive. Write them as the ECS API defines them (e.g. `desiredCount`). A key that differs from a known one only in case (e.g. `desiredcount`, `DesiredCount`), which v2 accepted, is an error. Other unknown keys are still ignored with a warning. Duplicate keys in an object are also an error. (#1126)
  ```console
  failed to load service definition ecs-service-def.json: unknown field "desiredcount" at /desiredcount: keys are case-sensitive, use "desiredCount"
  ```
- Keys in `driverOpts` and `labels` of `dockerVolumeConfiguration` in a task definition are sent as written. v2 upper-cased their first letter. (#1126)
- `verify` no longer validates `earlySuccessCriteria` in the service definition. ECS reports an invalid value when you deploy. `verify` checks what the AWS APIs do not report, and does not copy their validation rules. (#1131)

## GitHub Action

The GitHub Action has moved to [kayac/ecspresso-action](https://github.com/kayac/ecspresso-action). Replace the `uses:` line (#1120):

```diff
-      - uses: kayac/ecspresso@v2
+      - uses: kayac/ecspresso-action@v3
```

- `kayac/ecspresso@v3` is a deprecated wrapper that calls `kayac/ecspresso-action@v3` and prints a deprecation warning. `kayac/ecspresso@v2` is unchanged.
- The inputs are the same. kayac/ecspresso-action verifies the downloaded archive against `checksums.txt`, and no longer evaluates `args` with the shell: `args` is split on whitespace, and quotes are not interpreted.
- `version: latest` installs the latest stable ecspresso release regardless of the action version.

## New features

- Plugin functions (`tfstate`, `cloudformation`, `ssm`, `secretsmanager`) can be used in top-level configuration fields across all formats (YAML, JSON, Jsonnet). (#1023)
- Support pause lifecycle hooks for ECS service deployments. (#1047)
  - Add `continue` command to proceed or rollback deployments paused at lifecycle hooks.
  - Add `--wait-until=paused` option to `deploy`, `rollback`, and `wait` commands.
- Add `jsonrpc` mode to the `external` plugin. Starts the external command once and communicates over stdin/stdout with JSON-RPC 2.0, reducing startup overhead. (#1041)
- Support monitoring configuration for high resolution CloudWatch metrics. (#1045)
- Add `diff --exit-code`. It exits with status 2 when there are differences. (#1140)
- Support `gatewayConnectors` in the service definition to connect a service to Amazon ECS Gateway. (#1108)
- `verify` authenticates to Amazon ECR Public with the current session to avoid the anonymous pull rate limit, and falls back to anonymous access on failure. (#1112)

## Breaking changes (library)

These changes only affect users who import ecspresso as a Go library.

- Go module path bumped from `github.com/kayac/ecspresso/v2` to `github.com/kayac/ecspresso/v3`. Update import paths accordingly. (#1132)
- Go 1.27 or later is required to build ecspresso or import it as a library, because ecspresso uses `encoding/json/v2`. (#1111, #1126)
- Sentinel error types (`ErrNotFound`, `ErrSkipVerify`, etc.) replaced with `errors.New` sentinels. Use `errors.Is` instead of `errors.As`. (#1029)
- `App.RunTask` returns all started tasks (`[]types.Task`) instead of the first one. `App.WaitRunTask`, `App.DescribeTaskStatus`, and `App.DescribeTasksInput` take `[]types.Task` instead of `*types.Task`. (#1117)
- Several internals unexported: `WithConfigLoader`, `CLIParseFunc`, `ForSubCommand`, `ExportEnvFile`. (#1029)
- `ParseCLIv2` renamed to `ParseCLI`. (#1029)
- `WithPluginInstance` `AppOption` added to inject plugin runtime instances. (#1031)
